# Canonical demo

## Status

Future implementation. M0 demonstrates only reproducible foundation startup and health.

The eventual Buildathon story has four connected parts:

1. **Merchant agentization:** ingest/normalize an approved merchant and show readiness/capabilities.
2. **AI buyer:** express typed or voice intent, retrieve an exact product, enforce constraints, and
   create an understandable proposal.
3. **Graceful payment/finalization failure:** show authorization binding, idempotent execution, an
   injected unknown/failure outcome, and evidence-led reconciliation.
4. **Lifecycle/refund:** continue the persistent commerce thread into fulfilment and a safe,
   cap-enforced, idempotent refund.

Every displayed state must come from implemented behavior and measured evidence at demo time.
